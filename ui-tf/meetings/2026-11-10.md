## Alerts

[PR #1395](https://github.com/w3c/data-shapes/pull/1395), [Issue #541](https://github.com/w3c/data-shapes/issues/541)

**Discussion:**

- **Naming:** `shui:alert` is preferred over `shui:message`. It matches the convention of CSS frameworks, where an alert covers any severity (info, warning, error). Robert accepts `shui:alert`.
- **Severity:** Use a dedicated `shui:alertSeverity`, mirroring `sh:resultSeverity` in SHACL Core, instead of reusing `sh:severity` in a different context.
  - With a dedicated `shui:alertSeverity`, the qualified blank node form is no longer needed.
  - Limitation: one alert per property shape, which is acceptable and the same as for `sh:description`. A second property shape can be added if needed.
- **Bergi:** Notes a potential blank node issue if node expressions are supported for alerts. Will leave inline comments.

**Outcome:** Rename to `shui:alert`, add `shui:alertSeverity`, and drop the qualified blank node form.

## Property Roles

[Issue #1430](https://github.com/w3c/data-shapes/issues/1430)

**Discussion:**

- **Daniel:** Proposes removing the qualified role annotation with `sh:order` entirely, as its complexity is not justified. For a class hierarchy with conflicting property roles, walking the hierarchy and picking the closest definition is sufficient.
- **Bergi:** Use case of a patch graph that overrides a property role when graphs are merged.
- This could be done with `sh:deactivated` on an RDF 1.2 reified triple instead.

**Outcome:** Leave the `sh:order` mechanism for property roles out of the specification. Implementations can document their own approach.
