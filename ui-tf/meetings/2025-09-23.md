## Minutes

### SHACL Property Paths

We agree that the property path types predicate, inverse, and alternative will be supported in the spec in both view and edit modes.

Alternative paths will need to have restrictions in place for UI rendering, while leaving flexibility for implementors depending on their UX goals.

The remaining property paths are categorised as "complex property paths" with support only for view mode. We are however open to suggestions from the wider group on how we could support an edit mode for these complex property paths.

> View-only **should** be supported for complex paths while editing **may** be supported but is not defined in the specification.

## Actions
- Open to the wider group whether complex property paths should be supported in edit mode
