### Distinguishing between UI and non-UI shapes

**Daniel:** Should we add something like `shui:purpose` or `sh:purpose`? This is becoming more important as we start implementing things such as search facets.

**Bergi:** Open-world modellers may not agree with modelling this on top of validation shapes. We could still have these shapes, but simply not give them targets in the data graph.

**Daniel:** My assumption is that all shapes should be usable for validation. Another use case is GraphQL mappings, where SHACL shapes are used to map data to GraphQL output.

**Edmond:** Similar to how we use shapes for scoring, we can create shapes without defined targets and provide another class as the entry point, with shapes attached for particular use cases such as search facets, GraphQL mappings, and so on.
