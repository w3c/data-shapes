## Datatype validation

Discuss whether the SHACL UI specification needs to say anything explicit about datatype validation.

Key questions:

* Should the UI provide validation errors or feedback before the user submits?
* Should widgets perform any validation or normalisation themselves?
* How should widgets handle datatypes such as xsd:boolean, xsd:date, and xsd:dateTime?
* Should the specification leave ill-typed literals to the SHACL processor?
* Should this be mentioned in the error handling pattern instead?
* Is this ultimately an implementation detail rather than a normative requirement?

Proposed direction: do nothing specific for now. Delegate handling of ill-typed literals to the SHACL processor, and mention pre-submit validation or datatype feedback as a possible implementation approach in the error handling pattern.
