### SHACL Property Paths

- **Decision (tentative):** Unless further feedback is received from the wider group, no edit mode will be defined for _complex property paths_.
- **Discussion Points:**
    - Should we explicitly distinguish between **simple/direct** and **complex** property paths?
        - Agreed to revisit later when working on other sections.
    - View vs. edit mode: should **create** and **edit** be differentiated?
    - **Alternative paths:**
        - Argument for dropping support in edit mode: streamlines UI and reduces burden for implementors.
        - Counterpoint: not too difficult to implement (e.g., dropdown selector), but introduces a unique UI element that may not deliver much value to end users.
        - Alternative approaches could include **data shape profiles** or **logical constraints**.
        - Might be useful only for _advanced users_, whereas _normal users_ may benefit more from a simpler mode.
    - **Status:** Still under consideration — not ruled out.

### Mapping Property Paths, Focus Nodes and Value Nodes to UI
- **Current thinking:**
    - Move away from a one-to-one mapping of property shapes → form fields.
    - Instead, adopt a **property path–centric UI**:
        - Start at the root node shape.
        - Traverse the shape tree to collect constraints grouped by property paths.
    - This allows:
        - Combining constraints across multiple property shapes that share the same **property path**, **focus node**, and **value nodes** into a single Property Value UI element (PV).
        - Value nodes to inherit constraints from both referencing property shapes and node shapes that target them.
- **Example — Shapes Graph:**

```turtle
PREFIX ex: <urn:ex> PREFIX sh: <http://www.w3.org/ns/shacl#>
PREFIX schema: <https://schema.org/>

ex:RootShape a sh:NodeShape ;
    sh:targetClass schema:Person ;
    sh:property ex:Shape ; .

ex:Shape a sh:PropertyShape ;
    sh:path schema:name ;
    sh:minCount 1 ;
    sh:maxCount 1 ;
    sh:minLength 1 ;
    sh:node [
        sh:maxLength 10
    ]
.
```

- **Example — Data Graph:**
```turtle
PREFIX schema: <https://schema.org/>

<https://example.com/John-Doe> a schema:Person ;
    schema:name "Johnasdfas"
.
```

- **UI Implications:**
    - The PV for `schema:name` should reflect:
        - `sh:minLength 1`
        - `sh:maxLength 10`
    - Note: `sh:minCount` applies at the property path/focus node level, not directly to individual value nodes.
- **Outcome:**
    - This approach better supports complex constraints (e.g., logical constraints).
    - Considered a step in the right direction for SHACL UI development.
