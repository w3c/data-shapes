## Severity handling in UI rendering

- For rendering, the options are:
  - Treat all shapes as strict, regardless of whether they are warnings or violations.
  - Select only shapes with severity level sh:Violation.
  - Support collecting constraints from both warning-level and violation-level shapes.
- In SHACL Core 1.2, the validation report is now configurable to specify which severity levels are considered non-conformant, via sh:conformanceAllows or a similarly named predicate.
- We need to consider how confusing this may be for users, particularly in relation to constraints such as sh:minCount and sh:maxCount.
- This affects how we define the Node UI Component and Property UI Component, and how they collect constraints from their relevant shapes.
- A deprecation warning is a valid use case where fields should not be shown in forms, but should still appear in the data.
