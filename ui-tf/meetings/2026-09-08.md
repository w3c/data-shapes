### Topic: Conformance discussion from yesterday's plenary meeting
* Carine advised using fallbacks rather than failures for parts of the specification that an implementation does not support.
* Carine advised that an implementation not passing all tests does not necessarily mean that it is non-conformant with SHACL UI.
* Carine advised that implementations are expected to implement the normative parts of the specification.
* Carine advised that implementations may cherry-pick features, particularly for a user interface specification. She contrasted this with specifications such as WebRTC, where implementations are generally expected to follow the specification more strictly. The appropriate approach depends on the nature of the specification, and she suggested that user interface features should be driven by use cases.
* Carine advised that the WG should define features and their dependencies as groups, so that an implementation choosing to support feature B understands that it must also support any prerequisite feature A.
* Carine advised that, for a user interface specification, it may make sense to define conformance around the use cases that are in scope.
* The co-chairs suggested that, from this week onward, no new use cases should be added unless all members of the task force agree to support them.
