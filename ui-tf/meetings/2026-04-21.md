### Default namespace and local name generation

Discussion on UI default namespace and local name generation:

* introduce a configuration object
* consider a node expression for local name generation
* SHACL Rules can generate new blank nodes, but not new IRIs
* share the issue with the wider group to gather use cases for default namespace and local name generation

Proposed solution:

* `shui:defaultNamespace`
* `shui:localNameGenerate` or `shui:localNameBuild`, pointing directly to a node expression

Open question: where should the configuration object live?

* on an `owl:Ontology` instance
* as a blank node in the shapes graph
* as a named instance in the shapes graph

There may also be multiple configuration objects that are combined, with possible overrides and ordering via `sh:order`.

Multiple configurations could be composed through `owl:imports`, or combined by the application before the SHACL renderer starts.

### SHACL UI vocabulary / ontology

* There is already an existing SHACL UI vocabulary file:
  [https://github.com/w3c/data-shapes/blob/gh-pages/shacl12-vocabularies/shacl-ui.ttl](https://github.com/w3c/data-shapes/blob/gh-pages/shacl12-vocabularies/shacl-ui.ttl)
* New SHACL UI classes and properties would go into that file.
* Widget definitions would remain separate, as they are now.
