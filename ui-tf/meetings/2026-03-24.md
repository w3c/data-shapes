## `sh:severity`

Severity levels map to the following UI indicator styles:
| Severity | Colour |
|---|---|
| Info | Blue |
| Warning | Yellow |
| Violation | Red |

**Discussion:**
- Example: `maxCount 2` → violation; `maxCount 1` → warning. How should these map to UI behaviour?
- **Daniel:** At Triply, the team previously filtered for violation shapes only, but this proved to be a poor approach. The topic is complex.
- Daniel noted appreciation for the perspectives shared in the Signal chat.
- **Bergi:** Under SHACL 1.0, if a warning is elevated to a violation by the processor, the report will set `conforms` to `false`. In the current core spec, this is expressed as *"conforms disallows"*.
- **Daniel:** Favours treating this as an implementation detail, but recommends providing guidance in the error-handling section.
- **Bergi:** There is a legitimate use case for allowing users to save invalid data, or to load legacy data that violates constraints, with the expectation that the application will reconcile it later.
