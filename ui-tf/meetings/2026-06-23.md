## Implementations

Bergi noted that it would be beneficial to begin implementation work.

Robert asked whether there are any candidate implementations available today.

Ieben indicated that he already has a library implementing SHACL UI.

Daniel asked what level of implementation evidence is required.

Robert and Edmond clarified that, for Recommendation, each feature will require at least two independent implementations.

Daniel suggested that, based on current interest, there could potentially be implementations from Daniel, Ieben, and Edmond.

The group discussed how implementation status should be tracked.

Ieben referenced issue #827 and asked whether SHACL profiling mechanisms could be used to describe which SHACL UI features are supported by a given SHACL Renderer implementation.

Bergi cautioned that implementations and the specification may drift over time.

Edmond suggested that, at a minimum, at-risk features should be tracked.

Ieben proposed creating GitHub issues to track feature implementation status.

Bergi suggested using a single tracking issue with a standard implementation-reporting template.
