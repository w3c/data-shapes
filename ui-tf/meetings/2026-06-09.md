## PR #922: Adding display provider, resource filter, and SHACL-SPARQL pattern for autocomplete widgets

Link: https://github.com/w3c/data-shapes/pull/922

Bergi suggested considering node expressions, or an approach related to node expressions, instead of the current SPARQL `SELECT` pattern.

The group discussed the benefits and trade-offs between node expressions and SPARQL `SELECT`. One benefit of SPARQL `SELECT` is that implementations may wrap the query to provide features such as pagination. This would not be as straightforward with node expressions.

Daniel asked whether the two approaches could be combined while preserving the same behaviour.

Bergi suggested that the specification should include a dedicated subsection explaining how these specific property roles are used in this context.

Edmond asked whether global configuration could be used to add default pagination behaviour for node expressions.

Bergi noted that label resolution is not clearly defined in this section, and that there is overlap with how the label role is used in the examples.

### Actions

- Add a small subsection in the Label Resolution section explaining the label role.
- Where the label role is mentioned elsewhere, refer back to the roles section.
- Consider whether the proposal can be expressed using pure SHACL Core instead of introducing the new SHACL UI concepts “Display Provider” and “Resource Filter”.

Bergi asked whether anyone had a concrete example of how JSON APIs would work in this model.

Edmond suggested that some JSON integration ideas could be drawn from SPARQL Anything: https://sparql-anything.readthedocs.io/v0.8.0/
