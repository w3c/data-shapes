## External reference

Issue 846: https://github.com/w3c/data-shapes/issues/846

Display provider and resource filter

Edmond asked whether this could remain within SHACL Core as constraints, rather than introducing `shui:DisplayProvider` and `shui:ResourceFilter`.

Daniel said this was needed because SHACL Core has no concept of retrieving annotations.

Daniel also demonstrated a proof of concept. In the demo, the combined queries were performed using the JavaScript library Traqula.

The group discussed adding an informative note showing how the queries can be combined, including an example that uses a SERVICE clause.

If no Display Provider is specified, the behaviour would fall back to the standard label resolution mechanism defined by SHACL UI.

## Property for declaring a namespace for new instance data

Issue 855: https://github.com/w3c/data-shapes/issues/855

Daniel asked whether dash:stem could be used in some way:
https://www.datashapes.org/constraints.html#StemConstraintComponent

There was discussion about adopting `dash:stem` in shui, or possibly in SHACL Core.

Ieben asked whether this would also involve introducing `shui:defaultNamespace`, as mentioned in the issue.

A concern was raised about how `dash:stem` would work with existing data that do not belong to the namespace.

The group noted that this is difficult because `dash:stem` is a constraint, whereas the proposed `shui:defaultNamespace` is more of a configuration mechanism.

Edmond suggested that the group should consider a more general way to express UI configuration, so that it could cover `shui:defaultNamespace` and similar settings in future.

Robert noted that the same mechanism could potentially also be used to define a default language.

Validation errors and warnings
