## Label Resolution and Configuration

Robert has opened a PR for global configuration and would like to discuss how it should integrate with label resolution.

PR: [https://github.com/w3c/data-shapes/pull/900](https://github.com/w3c/data-shapes/pull/900)

The open question is whether label resolution applies only to instances in the data graph, or also to terms in the shapes graph.

For example, an imported shapes graph may contain classes or properties with `rdfs:label`. These labels should be preferred where available before falling back to the `sh:name` value on the property shape.

Decision: Prioritise labels from the data graph first, because the user controls the data graph, while the shapes graph may import external vocabularies.

Decision: Only one label configuration mechanism is needed.

Property labels: duplicate step 1 of section 7.2.1 so that it also checks the data graph.

## Testing

Use EARL reports for conformance reporting.

Open question: how do we prove the report? Current understanding: the report is submitted as evidence.

Testing should cover document subsections where behaviour is precise and testable, such as the scoring system and label/language resolution.

Other sections, such as widgets, may rely more on prose requirements and visual validation. There is precedent for this approach in W3C specifications such as WCAG.
