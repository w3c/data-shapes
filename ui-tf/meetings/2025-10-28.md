### Terminology

#### SHACL UI Processor vs. SHACL Renderer

We need to decide between **SHACL UI Processor** and **SHACL Renderer**.

A SHACL Renderer can operate in two modes:

1. **Manual mode:**  
   The renderer is provided with a data graph, shapes graph, focus node, and an explicit node shape.

2. **Automatic mode:**  
   The renderer is provided with a data graph, shapes graph, and focus node.  
   It determines the most appropriate node shape(s) automatically.

We could generalize this as:  
> A SHACL Renderer takes a data graph, a shapes graph, a focus node, and optionally a node shape.

The question remains whether we need distinct names for these two modes of operation.

---

#### Node UI Element and Property UI Element

We discussed the viability of several qualifiers for these components:

##### **Container**
- **Pros:** Implies containment, which fits the idea that a Node UI Container holds the resource corresponding to one or more node shapes.  
- **Cons:** In UI design, “container” is often used to describe layout or styling constructs. Since Node and Property UI Elements include **state**, **logic**, **event emitters**, and **rendering**, “container” may not convey their full behaviour.

##### **Component**
- **Pros:** “Component” is a well-established and widely understood term in UI design. It denotes a reusable building block that encapsulates **logic**, **state**, and **rendering**, matching the role of both Node and Property UI Elements.

##### **Element**
- **Pros:** “Element” is a familiar concept, especially in the web ecosystem (e.g., Web Components and Custom Elements). It suggests a tangible unit of the UI.

##### **Renderer**
- Our discussions naturally converged around the term **SHACL Renderer**.  
  We could adopt **Node Renderer** and **Property Renderer** accordingly.

> **Provisional decision:** Continue using **SHACL Renderer** as the umbrella term.

---

#### Singular vs. Plural Naming

Should these be named in singular or plural form?

- **Plural** may be justified since a single Node UI Element can aggregate multiple node shapes.  
  However, we may revisit this once implementation patterns stabilize.

---

#### SHACL Renderer Modes

We will prioritize work on **display mode** and **form mode**.  
**Query mode** and **facet mode** are not yet fully conceptualized and should be addressed after display and form modes are complete.
