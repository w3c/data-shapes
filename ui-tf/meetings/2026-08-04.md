## Inputs to the SHACL UI Renderer

### Meaning of `shui:inferenceGraph`

The group discussed what `shui:inferenceGraph` represents and whether it is an application-level configuration.

**Edmond:** We should clarify whether the renderer may receive a logical graph formed from the closure of multiple concrete graphs. This would allow the SHACL UI Renderer to remain agnostic about how the graph supplied to it is constructed.

**Daniel:** I am cautious about using the term *inference graph*. We need to give this parameter a clear name, comparable to *data graph* and *shapes graph*, so that it can be referenced consistently throughout the algorithms.

**Edmond:** Could we first outline the primary use cases and then use those to define the interface?

**Ieben:** Summarised the proposal described in [his comment on issue #609](https://github.com/w3c/data-shapes/issues/609#issuecomment-5176508591).

**Action:** Clarify the role of the global configuration and whether it is an application-level concept.

### Target resolution

The group discussed whether target resolution should be performed by the SHACL UI Renderer or by a separate application-level component.

**Ieben:** The top-level entry point is the SHACL UI Renderer, which renders a node UI component for each value node resolved by the target.

**Edmond:** Could we keep the SHACL UI Renderer focused on rendering the inputs it receives, with target resolution handled separately?

**Daniel:** We should refer directly to `sh:target` rather than define a separate target-resolution mechanism. I would prefer the renderer to receive a list of focus nodes, as this results in a cleaner architecture.

**Edmond:** We could define higher-level components, such as a multi-item list or search component, that perform custom target resolution and then pass the resulting focus nodes to the SHACL UI Renderer.

**Actions:**

* Create a pull request describing the proposed renderer inputs.
* Edmond to list possible higher-level components, including multi-item list and search components.
