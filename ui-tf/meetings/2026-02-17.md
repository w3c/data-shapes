### SHACL UI Task Force: PR 700 Review
**Status:** Move out of Draft (Pending comment on `shui:editor`)

#### 1. Boolean Editor Renaming & Implementation
**Consensus:**
- **Rename** `BooleanSelectEditor` to `BooleanEditor`.
- Specific widgets (e.g., `BooleanSelectEditor`, `BooleanSwitchEditor`) move to the **community registry**.
- The distinction between **mandatory** (checkbox) and **optional** (dropdown with null) is an **implementation detail**; this will be documented as a note in the spec.

#### 2. DetailsEditor & Nested Shapes
**Discussion:**
The group debated how to handle recursive rendering and when to trigger nested forms.
- **Ieben:** Suggested that including a nested shape usually implies the user wants to view the nested form.
- **Daniel:** Cautioned against automatic rendering due to recursion depth issues; currently, it only renders when explicit.
- **Edmond:** Highlighted that the **DASH specification** provides a good balance—it can switch to a "null" state or mark it as not applicable. He suggested **ranking it low** in the default scoring or **ranking it high** only when `shui:editor` is explicitly used.
- **Bergi:** Noted that relying solely on `sh:class` is risky now that it can be used in node expressions.

#### 3. Preferred Editors: `shui:editor` vs. Shapes Approach
**Stances:**
- **Ieben:** Prefers the **Shapes Approach** for its flexibility and uniform score calculation.
- **Bergi:** Prefers the **Non-Shapes Approach** to avoid conflicts when importing widgets.
- **Edmond (Neutral):** Noted that a non-shapes approach requires a clear definition for handling multiple `shui:editor`instances and a robust scoring system for fallback widgets.
- **Daniel (Neutral):** Concerned that a strict assignment approach in the JS pseudocode makes "repair mode" difficult to implement.
